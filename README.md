# 五岔路口交通灯相位优化设计 (Traffic-Light-Optimization)


## 📌 项目背景

本题模拟一个五岔路口的交通灯管理问题。路口共有 A、B、C、D、E 五个方向，其中 C 和 E 为单行道，共有 13 条可通行路线：

AB, AC, AD, BA, BC, BD, DA, DB, DC, EA, EB, EC, ED

由于车辆行驶路线之间存在交叉，部分路线不能同时通行（例如 E→B 和 A→D），而部分路线可以同时通行（例如 A→B 和 E→C）。本项目的目标是：设计一套交通灯分组方案，使得同一组内的路线互不冲突，且总的组数（信号相位）尽可能少。

## 🧠 设计思路

### 1. 问题抽象：图着色模型

将问题转化为图的顶点着色问题（Graph Coloring）：

- 顶点（Vertex）：每一条可通行路线视为一个顶点，共 13 个。
- 边（Edge）：如果两条路线存在冲突（不能同时通行），则在两个顶点之间连一条边。
- 颜色（Color）：每一种颜色代表一组交通灯（一个信号相位）。

约束：相邻顶点（有冲突的路线）不能着同一种颜色。
目标：使用尽可能少的颜色完成着色，即用最少的交通灯组数实现全部路线的通行管理。

### 2. 冲突关系分析

根据路口示意图，各路线之间的冲突关系如下：

- 孤立点（无冲突）：BA、DC、ED，这三条路线不与任何其他路线冲突，可以和任意路线同时通行。
- 第一组（无互相冲突）：AB、AC、AD，三者之间互不冲突，但与以下路线冲突：
  - 共同冲突对象：BC、BD、DA、DB、EB、EC
- EA 的特殊性：EA 与 AB、AC、AD 存在冲突，但与其他路线无冲突。
- 其余冲突关系：
  - BC 与 DA、DB 冲突
  - BD 与 DA、DB、EC 冲突
  - DA 与 EB、EC 冲突
  - DB 与 EB、EC 冲突
  - EB 与 BD、DB 冲突
  - EC 与 BD、DA 冲突

### 3. 算法选择：贪心着色算法

采用贪心着色算法（Greedy Coloring）：

1. 遍历所有未着色的顶点。
2. 为当前顶点分配一种已存在的最小可用颜色；如果所有颜色都冲突，则启用新颜色。
3. 在同一颜色下，尽可能多地将不冲突的顶点加入该颜色组。
4. 重复上述步骤，直到所有顶点完成着色。

贪心算法虽然不保证全局最优，但在本题的冲突图规模下（13 个顶点），能够得到最优解（4 组）。

## 💻 代码结构

| 函数 / 变量 | 说明 |
| :--- | :--- |
| route_names[] | 存储 13 条路线的名称 |
| adj[N][N] | 冲突矩阵，adj[i][j] = 1 表示路线 i 和 j 冲突 |
| init_conflicts() | 根据示意图初始化冲突矩阵 |
| color[N] | 存储每个顶点被分配的颜色（组号），初始为 -1 |
| main() | 执行贪心着色并输出分组结果 |

## 🚀 编译与运行

### 环境要求
- C 编译器（GCC / Clang / MSVC 均可）
- 标准 C 库

### 编译命令

gcc traffic_light.c -o traffic_light

### 运行

./traffic_light

## 📊 运行结果

程序输出的分组方案（示例）：

交通灯分组方案：
第 1 组（颜色 1）：AB AC AD ED BA DC
第 2 组（颜色 2）：BC BD EA
第 3 组（颜色 3）：DA DB
第 4 组（颜色 4）：EB EC

说明：由于贪心算法的顺序影响，具体分组结果可能略有不同，但总组数为 4 组，达到理论最优。

方案解读：
- 第 1 组：包含大部分无冲突路线，可同时放行。
- 第 2、3、4 组：包含存在冲突的路线，需错开放行。
- 共需 4 个信号相位，实现全部 13 条路线的安全通行。

由于 N 固定为 13，算法在实际运行中耗时极短（微秒级）。

## 📝 总结与展望

本项目将交通灯管理问题抽象为图着色问题，并使用贪心算法求得最优分组方案。方案共需 4 组交通灯，在保证安全的前提下，最大程度提高了路口的通行效率。

扩展方向：
- 引入遗传算法或模拟退火算法，探索是否有更优解。
- 加入实时车流量权重，动态调整各方向绿灯时长。
- 使用图形化界面（如 Qt 或 Web 前端）实时展示交通灯状态。
